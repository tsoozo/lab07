## Дүгнэлт (Хэсэг E)

Хамгийн үр дүнтэй нь Supermodel аялал байв: дэлгэцийн элемент бүрийг спецификацитай тулгахад BUG-01, 02, 04, 05, 09 гэсэн таван согог олдсон бөгөөд ихэнх нь анхны хуудсыг нээмэгц л харагдаж байсан. Couch Potato аялал (хоосон, утгагүй, хэт урт оролт) оролтын шалгалт огт байхгүйг илрүүлж BUG-03, 06, 07-г өгсөн. Fed-Ex аялал нэг номыг нэмэх → хайх → тоолуур → давхардуулах замаар дагахад BUG-11 (хайлт том/жижиг үсэг ялгадаг), BUG-12 (давхардал)-ыг илрүүлсэн. Saboteur аялал `curl`-аар UI-д харагддаггүй асуудлыг гаргасан: буруу JSON-д 200 OK буцаах (BUG-08), `&` тэмдэгт серверт `&amp;` болж хадгалагдах (BUG-10), мөн тоолуурын алдаа серверийн `/api/stats`-д байгааг баталсан (BUG-01). Charter-аас гадуур санамсаргүй ажигласан зүйл нь шинээр нэмсэн номын он API-д `"2001"` гэж текст хэлбэрээр хадгалагддаг, хайлтын дараа өмнөх «Ном нэмэгдлээ» мессеж хэвээр үлддэг явдал байв. Шалгагдаагүй үлдсэн нь: байхгүй id-г устгах (`DELETE /api/books/999`), гар (Tab/Enter) ашиглан ажиллах, хүртээмж, гар утасны дэлгэц, олон таб/зэрэг хүсэлт, хэт олон ном үеийн гүйцэтгэл — эдгээр нь дараагийн session-ий charter болно. Лаб 1-ийн Playwright тестээр хүлээгдэх утгыг тодорхой бичвэл мессеж (02), хоосон оролт (03), он (04, 06), хайлт (11), давхардал (12), тоолуур (01), 500 линк (09), `&amp;` (10), API статус (08) зэрэг ихэнх нь баригдах байсан. Харин «Устгах» товчны өнгө (05) болон урт оролтоор хүснэгт эвдрэх (07) нь зөвхөн хүний нүдээр (эсвэл тусгай visual regression тестээр) олдох согог бөгөөд exploratory тестийн давуу тал энд харагдаж байна.
